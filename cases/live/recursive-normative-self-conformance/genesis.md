# Genesis

## Perspective

The observer is a successor KFD steward attempting to change the normative
system after the Self-Conformance Profile became a published contract. From
this position, adopter-facing conformance rules and KFD's own governance can
drift apart unless the same exact-root obligations remain inspectable.

## Current ontology

The installed ontology already contains immutable Fact cuts, fact-bound trust,
participant-visible constraints, perspective, KFD-5 Candidate genesis and
qualification, Claim/Assessment/Decision/Admission separation, and the
Self-Conformance Profile's transition bundles and lifecycle gate.

## Methods

Genesis combines reconstruction pressure and structural compression. The
pressure is repeated reconstruction of how a normative system applies its own
rules. The compression hypothesis is that one named procedure could make the
recursive path legible. Neither method receives authority to qualify the
result.

## Evidence cut

The machine cut binds the current KFD-1, KFD-2, KFD-5, KFD-11, Profile
bootstrap anchor, Profile manifest, historical activation and Foundation
Revision records, this case, and the pre-number Candidate. Later evidence may
cite the containing Git commit without putting that commit into its own
preimage.

## Candidate object

`recursive-normative-self-conformance` is a proposed procedure requiring a
normative system's load-bearing self-change to traverse fixed-root genesis,
qualification, independent review, separate disposition, and explicit
admission or non-promotion.

## Claim boundary

The genesis claims that the composition is worth testing. It does not claim a
new irreducible Primitive, historical execution before the Profile existed,
semantic truth, successful qualification, numbering, or governance authority.
